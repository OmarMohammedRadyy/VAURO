# اقربلك - وثيقة متطلبات المنتج (PRD)

## 1. نظرة عامة على المشروع
- **اسم التطبيق:** اقربلك
- **الهدف:** منصة موحدة تجمع العملاء وأصحاب المتاجر والسائقين والمديرين لإدارة طلبات الطعام والبقالة والصيدليات والمنتجات الأخرى مع تجربة شراء وتوصيل شفافة وسلسة.
- **الميزة التنافسية الأساسية:** نظام "اقتراحات أقرب لك" الديناميكي الذي يوظّف بيانات الموقع في الوقت الفعلي لاقتراح أقرب المتاجر وأسرعها توصيلًا مع مقارنة زمن الوصول والتكلفة وتقديم العروض الملائمة.
- **التقنيات الرئيسة:** React Native (Vite) للواجهة، Ant Design UI، NestJS للواجهة الخلفية، SQL Server لقاعدة البيانات.

## 2. الشرائح المستهدفة والأدوار
| الدور | الاحتياجات الرئيسة | الصلاحيات |
|-------|-------------------|-----------|
| العميل | اكتشاف متاجر قريبة، إدارة السلة والطلبات، تتبع التوصيل، مراجعات | إنشاء حساب، تسجيل الدخول، تحديد الموقع، تصفح المتاجر، الدفع، تتبع الطلبات، إدارة العناوين والتفضيلات |
| صاحب المتجر | الاعتماد، إدارة الكتالوج والمخزون، رؤية التحليلات | تسجيل كممثل متجر، إدارة المنتجات والطلبات، التحليلات، إدارة السائقين |
| السائق | استلام الطلبات، تحديث حالة التوصيل، تتبع الأداء | تسجيل السائق، الاطلاع على المهام، تحديث حالة الطلب |
| المدير | الإشراف العام، إدارة المحتوى والتحليلات | إدارة المتاجر، الفئات، العروض، الطلبات، السائقين، إعدادات التطبيق |

### تدفقات المصادقة
1. صفحة التسجيل > اختيار نوع الحساب (عميل/صاحب متجر/سائق).
2. جمع الحقول المطلوبة بما في ذلك رفع الوثائق للبائعين والسائقين.
3. تحقق OTP عبر البريد أو الهاتف.
4. إرسال طلب اعتماد للبائع والسائق وللمدير للمراجعة؛ يُفتح حساب العميل تلقائيًا.
5. التوجيه إلى لوحة مناسبة بعد النجاح.

## 3. تدفقات التجربة والوظائف
### رحلة العميل
1. **الصفحة الرئيسية:**
   - تحديد الموقع تلقائيًا مع إمكانية التعديل.
   - أقسام: البحث، العروض، الفئات، الأقسام الفرعية، منتجات مختارة، اقتراحات الأقرب.
2. **صفحة المتجر:** عرض معلومات عامة، قوائم المنتجات، إضافة للسلة.
3. **السلة والدفع:** مراجعة الطلب، اختيار وسيلة الدفع، إدخال الكوبونات.
4. **تتبع الطلب:** تحديثات حالة في الوقت الفعلي.
5. **الطلبات السابقة والمراجعات:** أرشيف الطلبات مع القدرة على التقييم.

### رحلة صاحب المتجر
- نموذج الاعتماد.
- لوحة تحكم لإدارة المنتجات (CRUD)، المخزون، الطلبات، السائقين المرتبطين، والتحليلات.

### رحلة السائق
- تقديم طلب التوظيف.
- قائمة الطلبات المخصصة مع حالات التنفيذ.
- تحديث حالة التوصيل وتسجيل الأداء.

### رحلة المدير
- لوحة مركزية لإدارة المتاجر والفئات والعروض والكوبونات والسائقين والمنتجات.
- تحليلات شاملة على مستوى المنصة.

## 4. تصميم UX/UI
- **الأسلوب:** عصري، هادئ، نظيف، مع لمسات تقنية.
- **الألوان:** لوحة هادئة مع ألوان مميزة للعروض.
- **إمكانية الوصول:** دعم ARIA، قابلية الاستخدام للأشخاص ذوي الاحتياجات.
- **التجربة:** تنقل سريع، دعم متعدد اللغات، إشعارات فورية لحالات الطلب.

## 5. المتطلبات التقنية
- **الواجهة:** React Native عبر Vite، استخدام Ant Design.
- **الخلفية:** NestJS مع TypeScript، تصميم REST APIs مع إمكانية GraphQL لتقليل الطلبات.
- **قاعدة البيانات:** SQL Server مع فهرسة للحفاظ على الأداء.
- **الأمن:** JWT مع انتهاء صلاحية، تشفير البيانات الحساسة، حماية من SQL Injection/CSRF.
- **الأداء:** استخدام caching، WebSocket لتحديثات الطلب.
- **النشر:** خدمات مستقلة (frontend، backend، قاعدة البيانات) مع CI/CD.

## 6. مخطط البيانات (ملخص)
- **User:** id, name, email, password_hash, role, avatar_url, created_at.
- **CustomerProfile:** user_id, address, location, preferences.
- **SellerProfile:** user_id, store_name, category_id, address, tax_id, status, rating.
- **DriverProfile:** user_id, license_number, vehicle_info, availability.
- **Store:** id, seller_id, name, category_id, description, address, is_active, rating.
- **Category:** id, name, parent_id.
- **Product:** id, store_id, name, description, price, stock, image_url, is_active, category_id.
- **Order:** id, customer_id, store_id, driver_id, status, total_price, delivery_address, created_at, updated_at, payment_status.
- **OrderItem:** order_id, product_id, quantity, unit_price.
- **Cart:** customer_id, store_id, items.
- **Coupon/Offer:** خصائص الكود، القيمة، تاريخ الانتهاء.
- **Review:** id, user_id, store_id, rating, comment, created_at.
- **Notification:** id, user_id, type, message, read, created_at.
- **AdminSettings:** config_key, config_value.

## 7. الخوارزميات والتفاعلات الديناميكية
- **اقتراحات أقرب لك:**
  - حساب المسافة بين موقع المستخدم والمتاجر المتاحة.
  - تقدير زمن التسليم باستخدام بيانات توافر السائقين وتكدس الطلبات.
  - إظهار نتائج مرتبة (الأقرب، الأسرع، الأفضل تقييمًا) مع فلترة حسب السعر، العروض، التوصيل.
- **إدارة الطلب:**
  - حالات: قيد الانتظار، قيد التجهيز، في الطريق، تم التسليم، فشل.
  - تحديثات في الوقت الفعلي عبر WebSocket.
- **إدارة الدفع:** تكامل مع بوابات دفع محلية/دولية، تحديث الحالة آليًا.
- **التحليلات:** لوحات يومية/أسبوعية/شهرية للمدير والبائعين مع مقاييس مثل الإيرادات ومعدلات التوصيل.

## 8. متطلبات البيئة والإعداد
- Node.js + npm/yarn، NestJS CLI، Vite، بيئة React Native.
- SQL Server معد مع سكريبتات التهيئة وملفات `.env` مُدارة.
- هيكل monorepo مقترح: `apps/api`، `apps/mobile`، `apps/admin`، `packages/shared`.
- CI/CD (GitHub Actions) للتشغيل الآلي للاختبارات والنشر.

## 9. خارطة الطريق التنفيذية
1. **مرحلة التخطيط:** إكمال PRD، حالات الاستخدام، مخطط ERD، تعريف واجهات API.
2. **مرحلة إعداد البيئة:** إعداد المستودع، monorepo، قواعد البيانات، CI/CD.
3. **مرحلة النواة الخلفية:**
   - نماذج المستخدم والأدوار، RBAC.
   - خدمات المتاجر، المنتجات، الطلبات، السائقين، العروض.
   - مصادقة JWT، WebSocket لتتبع الطلب.
4. **مرحلة الواجهة:**
   - شاشات التسجيل/الدخول، اختيار الدور.
   - تجربة العميل الكاملة، لوحة البائع، لوحة المدير.
   - دمج نظام اقتراح الأقرب وتكامل الخرائط.
5. **مرحلة الاختبارات:** اختبارات قبول وأداء وأمان وتجربة المستخدم.
6. **مرحلة الإطلاق والتوسع:** نشر البيئات، مراقبة الأداء، تحسينات الميزة التنافسية.

## 10. قائمة التحقق للاختبارات والتقييم
- دعم بوابات الدفع وتدفق حالات الفشل.
- تنفيذ سياسة الخصوصية والتخويل.
- سرعة ودقة تحديد الأقرب.
- تزامن إدارة الطلبات، المخزون، والتوصيل.
- ملاءمة لوحات المدير والبائع لاحتياجاتهم.
- دعم الأجهزة المتعددة (ويب/موبايل).
