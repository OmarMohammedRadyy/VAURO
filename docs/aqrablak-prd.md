# وثيقة متطلبات المنتج وخطة التنفيذ لتطبيق "اقربلك"

## 1. هدف المشروع والميزة التنافسية
- **اسم التطبيق:** اقربلك.
- **الرؤية:** منصة موحدة تربط العملاء وأصحاب المتاجر والسائقين ضمن تجربة شراء وتوصيل شفافة تشمل المطاعم، البقالات، الصيدليات وغيرها.
- **الهدف الرئيسي:** توفير تجربة تصفح وشراء سريعة مع توجيه موقع تلقائي ودعم كامل لمراحل الطلب من الاختيار حتى التسليم.
- **الميزة التنافسية الأساسية:** خوارزمية "اقتراحات أقرب لك" التي تستخدم المواقع الفعلية للمستخدمين لتوليد قائمة ديناميكية بالمتاجر الأقرب، مع مقارنة زمن الوصول والتكلفة وإبراز العروض ذات الصلة.
- **التقنيات المعتمدة:** React Native (Vite) للواجهة، Ant Design كنظام تصميم، NestJS للـ Backend، وقاعدة بيانات Microsoft SQL Server.

## 2. الأدوار والصلاحيات وتدفقات المصادقة
### الأدوار الرئيسية
| الدور | أبرز الصلاحيات |
|-------|----------------|
| العميل | تسجيل/دخول، إدارة الموقع التلقائي، التصفح والبحث، إدارة السلة والدفع، تتبع الطلبات، كتابة المراجعات |
| صاحب المتجر | تقديم طلب اعتماد، إدارة المنتجات والمخزون، إدارة الطلبات، تحليل الأداء، إدارة السائقين |
| السائق | طلب توظيف، عرض الطلبات المسندة، تحديث حالة التوصيل، تقارير الأداء |
| المدير | إدارة المتاجر والفئات والمنتجات والعروض والسائقين، تحليلات شاملة، إدارة إعدادات التطبيق |

### تدفق التسجيل والمصادقة
1. صفحة التسجيل تعرض اختيار نوع الحساب (عميل، صاحب متجر، سائق).
2. جمع الحقول الأساسية المشتركة: البريد الإلكتروني، كلمة المرور، تأكيد كلمة المرور.
3. جمع الحقول الخاصة بكل دور:
   - **العميل:** الاسم، الهاتف، موقع افتراضي/تلقائي، عنوان أساسي اختياري.
   - **صاحب المتجر:** اسم المتجر، نوعه، العنوان، رقم التسجيل التجاري، شعار/صورة، بيانات الحساب البنكي.
   - **السائق:** الاسم، رقم الهاتف، رخصة القيادة، مستندات الدعم، صورة شخصية، الموقع الحالي.
4. التحقق عبر البريد أو الهاتف وإرفاق المستندات عند الحاجة.
5. إرسال طلب الاعتماد للأدوار التي تتطلب موافقة (صاحب المتجر، السائق، المدير). فتح الوصول مباشرة للعميل عند التحقق.
6. إعادة التوجيه بعد التسجيل إلى الواجهة المناسبة لكل دور.

## 3. بنية التطبيق وتدفقات الصفحات
### صفحات مشتركة
- صفحة التسجيل/تسجيل الدخول مع اختيار نوع الحساب.
- حالة الحساب: قيد التحقق، مقبول، مرفوض.

### تجربة العميل
1. **الصفحة الرئيسية:**
   - شريط علوي بالملف الشخصي والتنبيهات.
   - اكتشاف الموقع التلقائي مع خيار التعديل اليدوي.
   - أقسام البحث، العروض، الفئات الرئيسية والفرعية، المنتجات المختارة، وكتلة "الأقرب لك".
2. **صفحة المتجر/المطعم:** معلومات عامة، قوائم المنتجات، إضافة للسلة، تفاصيل التخصيص.
3. **السلة والدفع:** إدارة العناصر، اختيار وسيلة الدفع، تطبيق الكوبونات، تأكيد الطلب.
4. **تتبع الطلب:** متابعة الحالة في الوقت الحقيقي، خريطة لحركة السائق.
5. **طلباتي:** أرشيف الطلبات مع إمكانية إعادة الطلب وتقديم المراجعات.

### تجربة صاحب المتجر
1. **نموذج الاعتماد:** رفع المستندات وتحديد بيانات المتجر.
2. **لوحة التحكم:** حالة الطلبات الجارية، إحصاءات سريعة، تنبيهات الأداء.
3. **إدارة المنتجات والمخزون:** إضافة/تعديل/حذف، إدارة الصور، تحديد الفئات.
4. **إدارة الطلبات:** تحديث الحالات، التواصل مع العملاء، تخصيص سائقين.
5. **التحليلات:** إيرادات، عدد الطلبات، أوقات الذروة، تقييمات العملاء.

### تجربة السائق
- لوحة الطلبات المعينة، تفاصيل التسليم، أزرار تحديث الحالة (استلام، في الطريق، تم التسليم)، تتبع الأداء.

### لوحة المدير
- إدارة المتاجر والفئات، إدارة العروض والكوبونات، مراقبة الطلبات والسائقين، إعدادات النظام والتحليلات الشاملة.

## 4. التصميم وتجربة المستخدم
- **الأسلوب البصري:** تصميم عصري نظيف بلمسة تقنية، ألوان هادئة مع إبراز للأقسام الترويجية.
- **التفاعلات الأساسية:**
  - التوجيه التلقائي للموقع مع تحديث مستمر.
  - عرض مقارنات زمن التوصيل وتكلفة الطلب.
  - تنبيهات حالة الطلب والدفعات.
  - دعم تخصيص العناصر (ملاحظات الطلب للمطاعم، إلخ).
- **قابلية الوصول:** دعم ARIA، تباين ألوان مناسب، إعدادات لغة متعددة.
- **الأداء:** أولوية لسرعة التحميل والتنقل.

## 5. المتطلبات التقنية والتكوينات
- **Frontend:** React Native عبر Vite، Ant Design، إدارة الحالة (مثلاً Zustand أو Redux Toolkit).
- **Backend:** NestJS مع TypeScript، طبقات واضحة للخدمات والمستودعات.
- **قاعدة البيانات:** Microsoft SQL Server، استخدام TypeORM أو Prisma.
- **خدمات أساسية:** المستخدمون والأدوار، المتاجر والمنتجات، الطلبات والتوصيل، العروض والكوبونات، التحليلات، الموافقات.
- **الأمان:** JWT مع TTL، تشفير بيانات حساسة، تحقق صارم من المدخلات، حماية من SQL Injection وCSRF.
- **واجهات API:** RESTful مع دعم التصفية والفرز والصفحات، إمكانية إضافة GraphQL لسيناريوهات معقدة.
- **النشر:** واجهة أمامية مستضافة عبر Vite، API عبر NestJS، قاعدة بيانات مُدارة، CI/CD للتكامل المستمر.

## 6. مخطط قاعدة البيانات (مختصر)
```text
User (id, name, email, password_hash, role, avatar_url, created_at)
CustomerProfile (user_id, address, location, preferences)
SellerProfile (user_id, store_name, category_id, address, tax_id, status, rating)

Coupon (id, code, discount_type, value, min_spend, max_discount, expiration)
```

- علاقات أساسية: 1-1 بين User وملفات الأدوار، 1-N بين البائع والمتجر، المتجر والمنتجات، الطلب وعناصره، إلخ.

## 7. الخوارزميات والتفاعل الديناميكي
- **اقتراح الأقرب:** حساب المسافة باستخدام إحداثيات المستخدم والمتجر، تقدير زمن التوصيل وفق توفر السائقين وحركة المرور، عرض النتائج حسب القرب والتقييم والعروض.
- **الفلاتر والبحث:** فلاتر بحسب النوع، السعر، التقييم، العروض، التوصيل؛ دعم الفئات الفرعية.
- **تتبع الطلب:** تحديثات فورية عبر WebSocket أو Long Polling لحالات الطلب (قيد الانتظار، قيد التجهيز، في الطريق، تم التسليم، فشل).
- **الدفع:** تكامل مع بوابات دفع، ربط حالة الدفع مع حالة الطلب.
- **التحليلات:** مؤشرات أداء (الإيرادات، الطلبات، أوقات التسليم، تقييم العملاء) على مستويات العميل والمتجر والمدير.

## 8. إعداد البيئة والبنية التحتية
- تثبيت Node.js وnpm/yarn، إعداد NestJS وReact Native.
- إعداد SQL Server، استخدام ملفات `.env` لإدارة الأسرار.
- هيكل monorepo مقترح: `apps/api`, `apps/mobile`, `apps/admin`, `packages/shared`.
- إعداد CI/CD (GitHub Actions أو GitLab CI)، استراتيجيات النسخ الاحتياطي، مراقبة الأمن.
- تحسين الأداء عبر Caching، فهارس في قاعدة البيانات للحقول شائعة الاستعلام.

## 9. خارطة طريق التنفيذ
1. **مرحلة التخطيط:** إعداد PRD نهائي، توثيق حالات الاستخدام، تصميم المخطط البياني للبيانات وواجهات API.
2. **تهيئة البيئة:** إنشاء الهيكل البرمجي، إعداد قاعدة البيانات، ضبط CI/CD.
3. **النواة الخلفية:** بناء نماذج المستخدمين والتوثيق، إدارة الأدوار، خدمات المتاجر والمنتجات والطلبات والسائقين والعروض، إنشاء واجهات REST و WebSocket.
4. **الواجهة الأمامية:** تطوير تدفق التسجيل، صفحات العميل (الرئيسية، التفاصيل، السلة، الدفع، التتبع)، صفحات البائع والمدير، دمج التوجيه الذكي.
5. **الاختبارات والتقييم:** اختبارات قبول، أداء، أمن، قابلية استخدام.
6. **الإطلاق والتوسع:** نشر البيئات، مراقبة الأداء، تحسين ميزة "اقتراح الأقرب"، جمع ملاحظات المستخدمين.

## 10. أسئلة مراجعة وتقييم الجودة
1. هل التكامل مع بوابات الدفع متاح وسهل التهيئة؟
2. هل سياسات الخصوصية والتخويل مطبقة بصرامة؟
3. هل سرعة تحديد الأقرب تلبي توقعات المستخدم؟
4. كيف تتم معالجة حالات الفشل (انقطاع الشبكة، فشل الدفع)؟
5. هل لوحات المدير والبائع توفر البيانات الضرورية لاتخاذ قرارات سريعة؟
6. هل النظام يدعم الأجهزة المتعددة (ويب/جوال) بسلاسة؟
7. هل إدارة التوصيل والمخزون متزامنة وفعالة؟

## 11. ملحق: تعليمات تنفيذية للمطورين
- هذه الوثيقة تعمل كـ PRD/BRD مختصر ودليل تنفيذ.
- المخرجات المتوقعة:
  - مخطط قاعدة بيانات SQL Server مفصل مع ERD.
  - وثائق واجهات NestJS مع أمثلة للطلبات والاستجابات.
  - هيكل جاهز لمشاريع React Native/Vite وAnt Design.
  - واجهات العميل والبائع والمدير وفق الوصف أعلاه.
  - خوارزمية "اقتراحات أقرب لك" مع تكامل خدمة الموقع.
  - قوائم تحقق للأمان وتجربة المستخدم وتدفقات العمل.
- المعايير العليا: الأداء، الأمان، قابلية التوسع، سهولة الاستخدام، دعم إضافة فئات جديدة بسرعة.
